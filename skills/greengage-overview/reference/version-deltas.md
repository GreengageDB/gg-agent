# Greengage 6.x vs 7.x — full difference inventory

Lookup material. Every row verified by reading `refs/remotes/origin/7.x` and
`refs/remotes/origin/6.x` of `GreengageDB/greengage`. Paths are repo-relative.

**Never use a bare `origin/7.x` ref in a greengage clone** — local branches literally named
`origin/7.x` and `origin/7.x_new` exist and git silently prefers them. Always
`refs/remotes/origin/7.x`.

```bash
S7=refs/remotes/origin/7.x
S6=refs/remotes/origin/6.x
git show $S7:<path>
git ls-tree -r --name-only $S7 | grep <pattern>
```

## Base and identity

| | 6.x | 7.x | Source |
|---|---|---|---|
| PostgreSQL base | `9.4.26` | `12.22` | `configure.in:24` `[PG_PACKAGE_VERSION=…]` |
| `AC_INIT` product version | `6.0.0-beta.1` | `7.0.0-beta.0` | `configure.in:23` |
| Version string at runtime | `PostgreSQL 9.4.26 (Greengage Database <ver>) on …` | `PostgreSQL 12.22 (Greengage Database <ver>) on …` | `configure.in` `PG_VERSION_STR` |
| `VERSION` file | generated by `configure`, git-ignored | same | `configure.in` `echo $GP_VERSION_LONG > VERSION`; `.gitignore:71` `/VERSION` |
| Tag format | `6.31.0` | `7.4.1`, `7.5.0` — plain SemVer, no `v` prefix | `git tag`; the docs version selector publishes 6.31.0 and 7.5.0 |

Branch layout is the same on both lines: `7.x` and `6.x` are live; **`main` is a stale
mirror of 6.x**; there is no `6X_STABLE`/`7X_STABLE`.

## Terminology and environment

| | 6.x | 7.x |
|---|---|---|
| Node name in docs, messages, flags | master | **coordinator** |
| Data-directory env var | `MASTER_DATA_DIRECTORY` | `COORDINATOR_DATA_DIRECTORY`; `gpAux/gpdemo/gpdemo-env.sh` also exports `MASTER_DATA_DIRECTORY` as an alias |
| Unset-env error text | `Environment Variable MASTER_DATA_DIRECTORY not set!` (`gpMgmt/bin/gppylib/commands/gp.py:1207`) | `Environment Variable COORDINATOR_DATA_DIRECTORY not set!` (`gpMgmt/bin/gppylib/commands/gp.py:1230`) |
| Env script | `$prefix/greengage_path.sh` | same (`gpMgmt/bin/generate-greengage-path.sh`) |
| Catalog header for topology | `src/include/catalog/gp_segment_config.h`, defines `MASTER_DBID 1`, `MASTER_CONTENT_ID (-1)` | `src/include/catalog/gp_segment_configuration.h`, defines `COORDINATOR_CONTENT_ID (-1)` |

The **table name is `gp_segment_configuration` on both lines** with identical columns
(`dbid, content, role, preferred_role, mode, status, port, hostname, address, datadir`) and
identical symbolic values (`'p'/'m'`, `'u'/'d'`, `'s'/'n'`). Only the C header name changed.

## GUCs that change what you type

| GUC | 6.x | 7.x |
|---|---|---|
| `gp_role` | exists, boot value `dispatch` (`guc_gp.c:5079`); `assign_gp_role` (`cdbvars.c:519`) sets **only** `Gp_role` | exists, boot value **`undefined`** (`guc_gp.c:4590`); valid values `DISPATCH`, `EXECUTE`, `UTILITY`; `check_gp_role` allows a session to *downgrade* to `utility` only (`cdbvars.c:428`) |
| `gp_session_role` | exists, boot value `dispatch` (`guc_gp.c:5068`); `assign_gp_session_role` sets `Gp_session_role` **and** `Gp_role` | **no such GUC**, but the name is still accepted: `guc.c:4758-4763` `map_old_guc_names` remaps `gp_session_role` → `gp_role` in `find_option`, silently |
| `gp_resource_manager` | boot value `queue`; help text *"Only support \"queue\" and \"group\" for now."* (`guc_gp.c:5123`) | boot value **`none`**; *"Only support \"none\", \"queue\", \"group\" and \"group-v2\" for now."* (`guc_gp.c:4624`); `gpconfig:172` rejects anything else |
| `default_table_access_method` | does not exist | exists (`src/backend/utils/misc/guc.c:3792`) |
| `optimizer` | boot value `true` under `USE_ORCA` (`guc_gp.c:2109`), help *"Enable Pivotal Query Optimizer."* | same boot value (`guc_gp.c:1815`), help *"Enable GPORCA."* |
| `optimizer_trace_fallback` | exists, boot `false` (`guc_gp.c:2134`) | exists, boot `false` (`guc_gp.c:1840`) — *"Print a message at INFO level, whenever GPORCA falls back."* Set it before concluding a plan came from ORCA. |
| `gp_interconnect_type` | default `udpifc` (`guc_gp.c:5376`) | default `udpifc` (`guc_gp.c:4859`); on both lines `tcp` always, `proxy` only when built `--enable-ic-proxy` (`configure.in:819` 7.x / `:860` 6.x, default `no`, requires libuv) |

**Client utility mode — the spelling is not symmetric:**

| Spelling | 6.x | 7.x |
|---|---|---|
| `PGOPTIONS='-c gp_session_role=utility'` | works (native GUC, sets both `Gp_session_role` and `Gp_role`) | works (remapped to `gp_role`) |
| `PGOPTIONS='-c gp_role=utility'` | **rejected** — sets `Gp_role` only, so `postinit.c:1190` sees `Gp_role == UTILITY && Gp_session_role != UTILITY` and raises `FATAL: System was started in master-only utility mode - only utility mode connections are allowed` (`postinit.c:1194`) | works |

So `gp_session_role=utility` is the one form that works on both lines. The shipped tools
use the per-line spelling: 6.x `gpcheckcat:3685`, `gpcheckcat_modules/repair.py:131`,
`gpinitsystem:1332`, `gppylib/db/dbconn.py:165` all send `gp_session_role=utility`; 7.x
`gpcheckcat:2640`, `repair.py:129`, `gpinitsystem:1146`, `dbconn.py:204` send
`gp_role=utility`. On both lines `-c gp_role=utility` is also passed to `pg_ctl -o` to start
a *postmaster* in utility mode — that is a different thing from a client connection.

| | 6.x | 7.x |
|---|---|---|
| `DISTRIBUTED` clause | `DISTRIBUTED BY (column [opclass], …) \| DISTRIBUTED RANDOMLY \| DISTRIBUTED REPLICATED` (`doc/src/sgml/ref/create_table.sgml:36`) | identical (`:38`) |
| Partitioning | Greenplum-style only: `PARTITION BY partition_type (column) [ SUBPARTITION BY … ]` (`create_table.sgml:37-42`) | that **plus** PostgreSQL declarative `PARTITION BY { RANGE \| LIST \| HASH } ( column \| (expression) [COLLATE …] [opclass] , … )` (`create_table.sgml:33`) |

## `gp_toolkit`

| | 6.x | 7.x |
|---|---|---|
| Packaging | plain SQL: `src/backend/catalog/gp_toolkit.sql`, loaded by initdb | **extension**: `gpcontrib/gp_toolkit/` |
| Control file | — | `default_version = '1.9'`, `schema = gp_toolkit` |
| View count | 45 `CREATE VIEW` in `gp_toolkit.sql` — that is what you get | 58 in `gp_toolkit--1.0.sql` and 59 in `--1.3.sql`, but `CREATE EXTENSION` at `default_version = '1.9'` runs `--1.3.sql` plus `--1.3--1.4` … `--1.8--1.9`, so **64 views are installed**. The extra five come from `--1.3--1.4` (`gp_partitions`) and `--1.6--1.7` (`gp_table_size_skew_coefficients`, `gp_db_segment_files`, `gp_db_files_current`, `gp_db_files_current_unmapped`). |
| Installed where | every database, by initdb | `gpinitsystem` `CREATE_GPEXTENSIONS()` runs `CREATE EXTENSION gp_toolkit` in `template1` **and** `postgres` (`gpMgmt/bin/gpinitsystem:1553`) |
| Schema-name reservation | reserved | *"As of 7.0 we do not reserve 'gp_toolkit' because it has been made [an extension]"* (`src/backend/catalog/catalog.c:367`) |

Consequence on 7.x: a database created from `template0` has **no** `gp_toolkit` schema.
`CREATE EXTENSION gp_toolkit;` in that database fixes it.

## `gpcontrib/` contents

| 6.x only | Both | 7.x only |
|---|---|---|
| `credcheck`, `gp_array_agg`, `gp_check_functions`, `gp_error_handling`, `gp_parallel_retrieve_cursor`, `gp_percentile_agg`, `gp_pitr`, `gp_subtransaction_overflow`, `gpmapreduce`, `pg_partitions_nolock`, `quicklz`, `temp_tables_stat` | `gp_debug_numsegments`, `gp_distribution_policy`, `gp_inject_fault`, `gp_internal_tools`, `gp_legacy_string_agg`, `gp_replica_check`, `gp_sparse_vector`, `gpcloud`, `orafce`, `zstd` | `gg_tables_tracking`, `gg_wait_sampling`, `gp_exttable_fdw`, `gp_toolkit`, `pg_hint_plan` |

`gg_tables_tracking` (bloom-filter relation-change tracking for fast size calculation) and
`gg_wait_sampling` (a Greengage adaptation of `pg_wait_sampling`) are **Greengage-original**
— they do not exist in Greenplum.

|---|---|
